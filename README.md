# Sync Songs App

Sync Songs App is a desktop application for managing a local music library and preparing synchronized music collections for Android devices (for example, Saregama-style offline music workflows).

## Business context

People who manage large offline music libraries often need a simple workflow to:

- keep a curated library on desktop,
- review what is already available on a target phone/device,
- prepare and synchronize only the required tracks.

This project is focused on reducing manual file operations and giving a single desktop interface for library management and sync preparation.

## Product scope

### Current capabilities

- Import audio files into the app-managed library.
- Store and manage song records in SQLite.
- View library statistics (counts and combined size).
- Open newly added tracks directly in MusicBrainz Picard.
- Configure desktop music directory and phone destination path.
- Desktop UI shell with sections for Library, Devices, Sync, and Settings.

### In-progress / planned areas

Based on the project TODOs and existing module structure:

- Android device discovery and richer ADB operations.
- Library comparison and sync plan execution.
- End-to-end synchronization actions (push/delete/update status).
- Additional playback and media-related features.

## Architecture

The app is a hybrid desktop system:

- **Backend:** C++17 application using GTK + WebKitGTK host window.
- **Frontend:** React + TypeScript + Vite UI loaded inside WebKit.
- **Bridge:** JSON message protocol between frontend and backend.
- **Storage:** SQLite repositories for songs, devices, and settings.

### Key backend modules

- `src/core/` – domain models, repositories, DB, app paths.
- `src/features/library/` – library operations (import, stats, Picard integration).
- `src/features/configure/` – settings read/write and validation.
- `src/features/adb/` – device/ADB integration (partially implemented).
- `src/webview/` – WebKit app shell and frontend/backend event bridge.

### Key frontend modules

- `frontend/src/components/sections/` – page-level UI sections.
- `frontend/src/stores/` – application state stores.
- `frontend/src/lib/*Bridge.ts` – bridge helpers to talk to C++ backend.

## Development setup

### Prerequisites

Install required tools/libraries:

- `cmake` (>= 3.20)
- `ninja`
- `pkg-config`
- `gtk+-3.0`
- `webkit2gtk-4.1`
- `sqlite3`
- `gstreamer-1.0`
- `node` + `npm`

### Install frontend dependencies

```bash
cd frontend
npm install
```

### Run in development mode

1. Start frontend dev server:

```bash
cd frontend
npm run dev
```

2. In another terminal, configure and build backend:

```bash
cmake -S . -B build -G Ninja
cmake --build build
```

3. Run backend executable:

```bash
./build/sync-songs-app
```

In the current implementation, backend development mode loads the UI from `http://localhost:5173`.

### Build frontend for packaging

```bash
cd frontend
npm run build
```

### Installable output (local)

```bash
cmake -S . -B build -G Ninja
cmake --build build
cmake --install build --prefix "$PWD/install"
```

### Debian package

```bash
cmake -S . -B build -G Ninja
cmake --build build
cd build
cpack -G DEB
```

### Quality checks

Frontend:

```bash
cd frontend
npm run lint
npm run build
```

Backend:

```bash
cmake -S . -B build -G Ninja
cmake --build build
```
